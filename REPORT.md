# Architecture

The implementation is one TypeScript application controlling a local Chromium session, plus a fictional banking demo server. A genuine Gemini 3.5 Flash Lite run discovered a five-action savings lookup. The unchanged artifact then returned another member's balance and passed seven replay scenarios. Discovery made five API requests; replay makes none. Evidence distinguishes live discovery, unattended replay, a simulated operator, and a user-operated login walkthrough.

The discovery controller observes the rendered page/accessibility snapshot, requests one schema-validated action, and sends it through the shared browser action gateway. It does not receive a prerecorded sequence. The gateway checks policy, resolves the real control, executes it, and verifies the effect. The builder retains only successful actions, replaces invocation values with explicit parameter bindings, and adds an authored completion/extraction contract. Completion is checked after every action, avoiding an unnecessary final model call.

One discovery loop and one replay interpreter handle every task. The browser gateway owns mutations, application policy, and authentication; the session owns control state; the event sink persists sanitized evidence. The common runtime currently uses browser locator types for resolution, so full surface independence remains a future refactor. Modules run in one process, with bounded requests and timeouts rather than distributed services.

Inputs, outputs, named controls, identity invariants, and outcomes are task definitions. The original savings artifact is normalized in memory through a compatibility adapter before entering the common interpreter; its original bytes, digest, and discovery evidence are retained. All new discoveries emit the common schema. Schema numbers indicate artifact formats, not duplicate execution engines.

A genuine Gemini contact run recorded four actions in four requests, followed by successful different-input replay. Original events and the emitted artifact are in `evidence/contact-v2/`. Six automated replays check contact outputs and missing-member outcomes across both layouts. Separate development fixtures demonstrate two tasks through the same interpreter; they remain clearly distinguished from live discovery evidence.

The two optional extensions are cross-tenant reuse and an agent-facing capability API. A deployment-owned registry exposes the two discovered artifacts as JSON input/output schemas and invokes them by name through the same replay interpreter. A localhost bearer-token server validates arguments before creating a browser, accepts one invocation at a time, and excludes artifact-path/policy overrides from requests. The HTTP demonstration lists the catalog and verifies a real contact invocation without model calls; its caller is explicitly programmatic, not an LLM. The API uses fresh headless sessions and returns authentication blockers instead of embedding an operator workflow. It is synchronous and has no durable jobs or production identity system.

# Artifact schema

A strict Zod schema validates `schema_version`, capability identity/revision, application version, typed input/output declarations, extraction targets, ordered steps, postconditions, a named completion rule, handler-profile version, and provenance. Schema versions fail closed; capability revisions use positive integers. The demo input is a five-digit string, preserving leading zeros. Balance is a decimal string, avoiding binary floating-point conversion; the implemented application profile accepts USD.

Each click stores a reusable target and resulting path; each fill binds `member_id` and verifies the field value. Exact label/role targets identify the demo's controls without test IDs. CSS supports explicit extraction locations. Model-supplied transient references are not persisted; the gateway derives canonical descriptors from permitted controls. A successful first resolution is not treated as proof of reuse: the saved artifact is tested on another member. Extraction targets for member identity, account kind, balance, and currency are serialized and independently tested with changed selectors.

Completion and business handlers are deliberately authored application semantics, not claims that one happy-path run discovered all exceptions. They are referenced by version in the artifact. The automated evidence manifests bind their replays to the original artifact file's SHA-256 digest; the earlier human-login run records its invocation path but did not log an artifact digest. Original discovery bytes are preserved. There is no arbitrary code, general loop construct, or model-driven locator repair in replay.

The common format serializes named elements, parameter schemas, output types/sensitivity, scoped identity invariants, business outcomes, and completion conditions. Discovery selects declared elements or exact descriptors from observed controls; it does not receive a prewritten sequence. The recorder binds inputs symbolically, checks action effects, and records task-digest provenance. Reference validation rejects missing elements/inputs and mismatched fill checkpoints. Ordered locator fallback permits zero matches to advance but stops on ambiguity. Outputs are validated and identity assertions rechecked before returning; no output values are persisted in events.

# Determinism & error handling

Before acting, replay validates the entire artifact, input, declared actions, and destination checkpoints against policy. Every target must match exactly one visible enabled control. Fills replace and verify values; clicks wait for navigation within a finite bound and check the recorded path. Final extraction validates member identity, savings account kind, uniqueness/visibility, decimal format, and currency. The same rules run for every invocation; live balances may differ.

`MEMBER_NOT_FOUND`, `NO_SAVINGS_ACCOUNT`, and `AMBIGUOUS_ACCOUNT` are business outcomes scoped to the correct screen and member. Slow responses use bounded waiting. Unknown states produce a failure identifying the step and expected/observed condition, plus sanitized structural evidence with execution phase, route, target count/actionability, and checkpoint result where available. Successful actions record a postcondition verification code. Unavailable controls before dispatch may request a human intervention and retry once after validation. Already-dispatched clicks are never blindly repeated. Unknown mutating actions are blocked, so transaction reconciliation is not implemented in this read-only slice.

Discovery uses a flat structured response schema, normalizes omitted optional fields, and validates tool bindings before dispatch. Repeated failures/no progress request human intervention in headed mode and stop with a structured error in unattended mode. Six API attempts per run and 15-second spacing are defaults; optional transient retries count against that same budget. HTTP 429 stops immediately with sanitized quota-scope diagnostics. These controls are per run, not a project-wide quota service.

# Heterogeneity & multi-tenant

The chosen surface is server-rendered web HTML with forms and no automation-only identifiers. The browser mutation gateway is shared; adapting the current browser-oriented resolver to desktop accessibility would require a separate implementation. Target variants are explicitly web-oriented today; a desktop adapter must reject them until a compatible accessibility/visual target type and deterministic resolver exist. A configured named-frame resolver now demonstrates replay inside a same-origin iframe with table markup and an unlabeled field resolved through scoped CSS. Duplicate frames/controls stop explicitly. Raw coordinates and arbitrary nested/cross-origin frames are not claimed to be portable.

Two authored tenant profiles now reuse the exact discovered artifact. Harbor has the original labels and description list; Summit has different labels and an account table with different attributes. Profiles configure a local base URL, tenant/version markers, and known locator slots; they cannot add steps, routes, or permissions. Runtime policy remains authoritative. Wrong-tenant and unsupported-version markers fail preflight. Four real browser runs cover two members per tenant without model calls, with exact artifact-file and profile digests in `evidence/tenant-reuse/`. Routes and business semantics remain shared; this demonstrates configured reuse, not automatic generalization. Desktop and cross-tenant deployment infrastructure remain design-only.

A second, independent inventory application uses the same engine with a generic application profile and policy: different routes, metadata, field names, records, and outputs. Its task contains output targets and business assertions but no action controls. Discovery can record native label/role targets or a table-neighbor relationship for unlabeled inputs with changing IDs; invented targets are rejected and multiple matches stop. One inventory artifact replays across two label variants and two items; missing-item and ambiguous-control scenarios are also verified. This evidence uses an injected decision provider and is explicitly a development fixture, not genuine model discovery. Application onboarding still requires authored semantics, permissions, and compatible HTML interactions. Automatic adaptation to arbitrary apps is not claimed.

Legacy perception additionally recognizes explicit/wrapping labels, referenced accessible names, placeholders, titles, and nearest-row labels. Discovery validates alternative descriptors against the same live node before saving a bounded candidate list. Nested tables are isolated by the input's nearest row; generated IDs and input values are not recorded as locators. Browser tests demonstrate loss of an accessible label with successful deterministic fallback, while ambiguous matches stop before dispatch. Candidate index and match count are persisted without label/value text. This broadens supported HTML patterns, not the action vocabulary or desktop support.

# Escalation & handoff

Headed CLI runs expose a local dashboard showing tenant, progress, authentication guidance, and final status. It delegates Resume/Cancel to the existing handoff controller and shows no financial outputs. The same dashboard spans interventions and remains available for 60 seconds after completion.

An authentication blocker, stuck discovery, or supported replay blocker yields an intervention containing capability, run, step, reason, and sanitized state evidence. Automation stops at a settled action boundary. A localhost operator page exposes Resume/Cancel while the same headed browser stays open. The operator resolves the blocker there; no fresh browser loses entered context. Resume passes through validation; premature/duplicate submissions are rejected. Failed or timed-out interventions terminate, and a late validation callback cannot restore automation ownership.

The current runner executes actions sequentially. Gateway ownership checks reject automated actions during human control; direct local mouse/keyboard access is a trusted-operator boundary rather than remote input fencing. Capture-phase instrumentation records manual click/change/submit/navigation event types without entered values. Browser chrome and OS actions are outside that capture. Authentication resumes at the same URL after identity checks; final-output intervention can accept completed extraction. A missing-control intervention requires that control to become actionable again. Arbitrary manual advancement through the remaining workflow is not inferred. An assisted discovery is not published because manual steps are not compiled into a reusable artifact.

Automated tests and curated replay evidence exercise a simulated operator in the same live session and verify assisted success. A later user-operated login walkthrough completed with assisted success. Its original sanitized events and a summary are preserved in `evidence/human-login/`, separately from simulated-operator evidence. The README provides the exact manual demonstration commands; the evidence does not mislabel the simulation as human activity.

# Safety

Policy is enforced in code against origins/routes, action classes, actual control attributes, and allowed control names. Artifacts/model responses cannot grant permissions. Transfers and unknown controls are blocked. Search requires an effective GET submission to the permitted form route in the current document; fills require text/search fields in that form. Request interception covers the demo's navigation and subrequests; service workers, WebSockets, and additional windows are blocked or rejected. This is not an OS/network sandbox or a proof that arbitrary hostile websites are safe. Unknown dialogs are dismissed and execution stopped.

Only fictional data is used. Credentials remain in ignored `.env`; request headers and raw provider errors are never logged. Persisted events contain operational codes/counts, and failure snapshots contain structure without raw page text. Returned balances appear only at the caller boundary. Provider observations contain synthetic page data; deployment against actual regulated records would require an additional redaction/authorization boundary. Operator URLs are local bearer links excluded from evidence. Free-tier billing remained disabled; no paid fallback was enabled.

# Cuts

No distributed workers, production authentication, database, desktop implementation, visual-only targeting, cross-tenant deployment, unrestricted workflow language, or model-assisted replay. One engine executes both the original savings artifact and the contact workflow. Application-specific authentication markers, control permissions, and compatibility rules are supplied by validated profiles and policies. The interpreter uses navigation-based click checkpoints; arbitrary single-page interactions need further support. A formal approval catalog, broader vendor profiles, stronger content-aware failure screenshots, and durable session recovery are next steps. A user-operated login walkthrough, genuine discovery for both workflows, and model-free replay are evidenced. The repository includes the source, setup instructions, design report, and demonstration evidence.

The local demo additionally offers staff login and a simulated verification challenge, including wrong/expired codes and an injected mid-workflow expiry. Authentication remains human-operated; the saved capability excludes credentials. This is an in-memory simulator with a fixed demonstration code, not production MFA or a real bank integration.
